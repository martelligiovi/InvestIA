# GHunt email adapter

A standalone, injectable SeedBox for `gmail.com` and `googlemail.com` email seeds. It also manages the GHunt Google session used by the backend. Run only with the operator's authorization; the offline tests never contact Google.

`createGhuntBox(runner)` requires an injected runner. `createGhuntProcessRunner({ sessionHome, pythonExecutable })` runs GHunt without a shell using `python -B -c 'from ghunt.ghunt import main; main()' email --json <report> -- <email>`. The option terminator protects service-valid local parts starting with `-`; the authentic GHunt 2.3.4 argument parser accepts it (verified offline against the wheel's `cli.py`). The caller must supply an existing, absolute, persistent **private** credential home; the runner sets both HOME and USERPROFILE to it. On POSIX the runner rejects a home not owned by the current user or accessible by group/other mode bits. On Windows POSIX mode bits do not verify ACL privacy: the caller must provision and verify an appropriately restricted ACL. The caller must also secure parent directories, ACLs on all platforms, and the output root; mode checks do not prove privacy against privileged users or races. GHunt may refresh credentials there. Do not use a temporary report directory as the credential home, share it between users, or log its contents. The caller owns authorization, session lifecycle and isolation, including concurrent access.
## Google session

`createGhuntSession({ sessionHome, pythonExecutable })` stores one GHunt session under `<sessionHome>/.malfrats/ghunt/creds.m`. `connect(code)` accepts only a [GHunt Companion](https://github.com/mxrch/ghunt_companion) export (base64 JSON with an `oauth_token` starting `oauth2_4/`), sends it to Python on stdin (never argv), and runs the non-interactive equivalent of `ghunt login` choice 2 in a staging home, so a failed attempt keeps the previous session. States are `connected`, `requires_connection` and `invalid_session`; the last is recorded when a scan fails with an upstream session error and cleared by reconnecting or `disconnect()`. `createSessionBoundRunner(session, runner)` serializes scans with session changes. The stored master token grants broad access to the Google account: treat the session home like a password.

Reports use a fresh temporary directory, removed after each run. Stdout and stderr are drained; a combined bounded 4 KiB tail is kept in memory for classification, and separate bounded 64 KiB tails are kept for traceback diagnostics. Raw output and exception messages are never stored or logged. On an unclassified nonzero exit, the error detail contains the exit code or signal, an allowlisted final exception type, and up to eight allowlisted traceback frames (normalized source name, line and function). Unknown types are reported as `unparsed traceback`; unknown paths and functions are omitted. Only a fixed whitelist of exact installed source paths is recognized, so other installations and truncated tracebacks may provide less detail. The first matching frames are retained (at most eight and subject to a length limit): these are normally the outermost, not necessarily those nearest the failure. Stderr takes precedence over stdout when both contain a traceback. The public API continues to mask execution failures. Time and output limits apply.

Traceback details are diagnostic hints, not proof of the cause. A traceback header embedded in an exception message can be mistaken for the last header, producing an unparsed or misleading allowlisted exception and frames, including a message-controlled line number. Python 3.11 `ExceptionGroup` tracebacks currently fall back to `unparsed traceback`. Neither case copies arbitrary messages or paths into the detail.

A successful exit with no JSON report is `not_found` only when GHunt explicitly reports that the target was not found or is not a public Google account; otherwise it is `missing_report`, not proof that the account does not exist. An unsafe or unreadable report remains an error. A nonzero exit with either not-found message is also `not_found`, and the box returns no finding. An upstream `GHuntInvalidSession` or `GHuntLoginError` is `invalid_session`. Other failures have generic codes. Profile extraction only accepts a PROFILE_CONTAINER profile with personId and retains the ID, full name and a non-default HTTPS photo without query, fragment or userinfo. The report may contain private data; it is not returned as a finding. `test/fixtures/ghunt-2.3.4-email-report.json` was produced offline by the authentic 2.3.4 `Person` objects and `GHuntEncoder` with synthetic values, not by a live scan. GHunt 2.3.4 no longer populates names, so `fullname` is normally absent.

The container installs GHunt from upstream commit `11b845b0cea6534d85f9b8cde467a3e6ef00d452` and its pinned dependencies into a dedicated Python environment; the adapter itself does not install GHunt. Do not install it globally.

Offline checks from the repository root:

```sh
node --experimental-strip-types --test APP/packages/adapter-ghunt/test/*.test.ts
node APP/node_modules/typescript/bin/tsc --noEmit -p APP/packages/adapter-ghunt/tsconfig.json
```
