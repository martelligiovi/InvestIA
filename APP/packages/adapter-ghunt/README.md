# GHunt email adapter

A standalone, injectable SeedBox for `gmail.com` and `googlemail.com` email seeds. It also manages the GHunt Google session used by the backend. Run only with the operator's authorization; the offline tests never contact Google.

`createGhuntBox(runner)` requires an injected runner. `createGhuntProcessRunner({ sessionHome, pythonExecutable })` runs GHunt without a shell using `python -B -c 'from ghunt.cli import parse_and_run; parse_and_run()' email --json <report> -- <email>`. Calling `parse_and_run` directly skips GHunt's banner and its startup update check, an unhandled request to GitHub that made runs fail on a slow connection. The option terminator protects service-valid local parts starting with `-`; the authentic GHunt 2.3.4 argument parser accepts it (verified offline against the wheel's `cli.py`). The caller must supply an existing, absolute, persistent **private** credential home; the runner sets both HOME and USERPROFILE to it. On POSIX the runner rejects a home not owned by the current user or accessible by group/other mode bits. On Windows POSIX mode bits do not verify ACL privacy: the caller must provision and verify an appropriately restricted ACL. The caller must also secure parent directories, ACLs on all platforms, and the output root; mode checks do not prove privacy against privileged users or races. GHunt may refresh credentials there. Do not use a temporary report directory as the credential home, share it between users, or log its contents. The caller owns authorization, session lifecycle and isolation, including concurrent access.
## Google session

`createGhuntSession({ sessionHome, pythonExecutable })` stores one GHunt session under `<sessionHome>/.malfrats/ghunt/creds.m`. `connect(code)` accepts only a [GHunt Companion](https://github.com/mxrch/ghunt_companion) export (base64 JSON with an `oauth_token` starting `oauth2_4/`), sends it to Python on stdin (never argv), and runs the non-interactive equivalent of `ghunt login` choice 2 in a staging home, so a failed attempt keeps the previous session. States are `connected`, `requires_connection` and `invalid_session`; the last is recorded when a scan fails with an upstream session error and cleared by reconnecting or `disconnect()`. `createSessionBoundRunner(session, runner)` serializes scans with session changes. The stored master token grants broad access to the Google account: treat the session home like a password.

Reports use a fresh temporary directory, removed after each run. Stdout and stderr are drained; a combined bounded 4 KiB tail is kept in memory for classification, and separate bounded 64 KiB tails are kept for traceback diagnostics. Raw output and exception messages are never stored or logged. On an unclassified nonzero exit, the error detail contains the exit code or signal, an allowlisted final exception type, and up to eight allowlisted traceback frames (normalized source name, line and function). Unknown types are reported as `unparsed traceback`; unknown paths and functions are omitted. Only a fixed whitelist of exact installed source paths is recognized, so other installations and truncated tracebacks may provide less detail. The first matching frames are retained (at most eight and subject to a length limit): these are normally the outermost, not necessarily those nearest the failure. Stderr takes precedence over stdout when both contain a traceback. The public API continues to mask execution failures. Time and output limits apply.

A nonzero exit whose final traceback exception is `httpx.ConnectTimeout`, `httpx.ConnectError` or `httpx.ReadTimeout` is classified as `network_timeout`, unless a higher-priority session or not-found marker applies. The runner retries this code once, after 30 seconds by default; `retryDelayMs` configures the delay (including zero for offline tests). The second failure is returned as-is, with no further retry. The session remains connected after `network_timeout`. Each attempt has its own 15-minute default process timeout, so a retry can occupy the serialized session for up to roughly 30 minutes 30 seconds plus setup and cleanup; session changes wait until it finishes. Traceback details on `network_timeout` use the same allowlisted, non-sensitive shape as `process_failure`.

Traceback details are diagnostic hints, not proof of the cause. A traceback header embedded in an exception message can be mistaken for the last header, producing an unparsed or misleading allowlisted exception and frames, including a message-controlled line number; this can also affect network classification and retry. Python 3.11 `ExceptionGroup` tracebacks currently fall back to `unparsed traceback`. Neither case copies arbitrary messages or paths into the detail.

A successful exit with no JSON report is `not_found` only when GHunt explicitly reports that the target was not found or is not a public Google account; otherwise it is `missing_report`, not proof that the account does not exist. An unsafe or unreadable report remains an error. A nonzero exit with either not-found message is also `not_found`, and the box returns no finding. An upstream `GHuntInvalidSession` or `GHuntLoginError` is `invalid_session`. Other failures retain their existing codes. Profile extraction only accepts a PROFILE_CONTAINER profile with personId. Each data type becomes its own finding (`category`), so the workspace stacks them under the GHunt action: `Google account` (always: ID and, when present, user types, entity type, customer ID, enterprise flag), `Name`, `Profile photo`, `Cover photo`, `Last profile edit` (only a valid date in GHunt's `YYYY/MM/DD HH:MM:SS (UTC)` format), `Google services` (activated apps), `Maps` (positive counts of allowlisted statistics and the public contributions URL), `Calendar` (summary, time zone and number of public events) and `Play Games` (display name, gamertag, title, number of played games and achievements). Empty, absent and default sections add no finding. Free-text values (names, user types, services, entity type, customer ID, calendar summary and time zone, Play Games names and title) are dropped when longer than 128 characters, containing an `@` or control characters, so a public calendar named after an email address keeps only its time zone and event count. Photos (profile, cover and Play Games avatar) are kept only when non-default HTTPS URLs on Google image hosts (`*.googleusercontent.com`, `*.ggpht.com`) without query, fragment (even empty markers) or userinfo. Event contents, reviews, emails, calendar IDs and other report fields are never retained. The report may contain private data; it is not returned as a finding. `test/fixtures/ghunt-2.3.4-email-report.json` was produced offline by the authentic 2.3.4 `Person` objects and `GHuntEncoder` with synthetic values, not by a live scan. GHunt 2.3.4 no longer populates names, so `fullname` is normally absent.

The container installs GHunt from upstream commit `11b845b0cea6534d85f9b8cde467a3e6ef00d452` and its pinned dependencies into a dedicated Python environment; the adapter itself does not install GHunt. Do not install it globally.

Offline checks from the repository root:

```sh
node --experimental-strip-types --test APP/packages/adapter-ghunt/test/*.test.ts
node APP/node_modules/typescript/bin/tsc --noEmit -p APP/packages/adapter-ghunt/tsconfig.json
```
